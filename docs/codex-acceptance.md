# Codex 优先版：本地合成验收

2026-10-24。当前支持入口为 Codex Skill + 本地 STDIO MCP 连接器。千问等客户端暂缓。没有部署服务、调用模型推理 API、使用真实简历或连接正式 OfferPath 账户。

## 自动化检查

全套 98 项合成测试通过：原执行器与配置演示 30 项、共享 HTTP 传输 20 项、远程接口适配 12 项、共享业务层 24 项、新 Codex STDIO 入口 12 项。

新增检查通过实际子进程验证初始化、通知、工具及资源调用、真实 PDF 字节、本人确认门槛、合成同步与持久化。还覆盖动态端口重启后的链接更新、同工作区进程独占、虚拟环境解释器路径保留，以及 EOF、SIGTERM 和输出断管时关闭 HTTP/SQLite。生成的 Codex TOML 只包含启动路径，不包含凭据，不修改全局配置。

## 本机 Codex 客户端验收

本机 Codex app-server（0.163.0-alpha.11.2）通过实际客户端协议建立临时会话并连接 STDIO 服务，状态为 connected，发现 9 项工具。使用内存配置覆盖，关闭其他连接，并使用本机拒绝端口的无认证模型提供器；没有发送模型回合或推理请求。

通过该客户端实际调用 `list_jobs` → `get_context` → `save_draft` → `get_pdf`，并以 `mcpServer/resource/read` 取回实际 PDF。虚构集成岗选择接口接入、SQL 数据质量及管道测试事实；Kubernetes 生产经验保持缺口。PDF 为中文 A4 一页、70,574 字节，资源字节及 SHA256 一致，实际渲染检查无缺字、重叠或裁切。

工具列表没有本人批准功能；调用不存在的批准工具被拒，PDF 仍处于未批准状态。此阶段没有报告投递或同步记录。

## 本地浏览器闭环

关闭上述客户端后重启同一合成工作区，实际 PDF、版本、事实引用保持不变，审阅链接更新到新端口。仅在这个虚构资料测试中模拟用户登录、查看并确认精确 PDF，然后通过 STDIO 工具登记明确标注“没有真实申请”的模拟结果、同步到本机假台账。实际留档附件回读一致，再模拟检查实际留档预览，记录达到 `complete`。

验收口令、工作区、数据库、PDF、日志和截图全部保留在仓库外；不作为公开项目资料发布。真实使用时 AI 不得读取审阅口令或代替本人批准材料。

## 尚未验收

- 上述是实际 Codex app-server 的工具连接和调用验收，不代表桌面 GUI 新用户安装已经一键可用；未修改作者的全局 MCP 配置。
- 草稿由合成测试提供，未测试模型推理效果或账号额度，不承诺永久免费或无限使用。
- 本人确认仍需打开本地 PDF 审阅卡，尚非对话窗口内的可信文件确认。
- 正式 OfferPath 授权、普通用户账户联调及网站自身的附件预览仍需独立验收。`complete` 在连接器中表示实际附件回读和本地预览完成，不代表招聘方收到申请。
- 原有 `agent.py` 的正式申请包、实时去重、发送锁与云端预览要求继续保留；合成记录不能为真实投递放行。
